## 고객 흐름 구현 상태

검색·광고·SNS → 랜딩페이지 → 사례 확인 → 가격 또는 작업 과정 확인 → 사진 전송 → 상담 → 견적 → 예약

| 단계 | 구현 상태 | 근거 |
|---|---|---|
| 검색·광고·SNS | 구현됨 | `lib/keyword-slugs.ts` 지역+서비스 랜딩, `app/sitemap.ts` |
| 랜딩페이지 | 구현됨 | `app/landing/[slug]/page.tsx`, 카테고리 동적 페이지 |
| 사례 확인 | 구현됨 | `/cases`, `/cases/[id]`, `lib/case-data.tsx` |
| 가격 또는 작업 과정 확인 | 일부 구현 | process는 있으나 구조화 가격표는 확인 불가 |
| 사진 전송 | 구현됨 | 사진 상담 CTA 문구와 카카오톡 연결 컴포넌트 |
| 상담 | 외부 채널 의존 | 카카오톡/전화 연결 이후 데이터는 저장소에 없음 |
| 견적 | 확인 불가 | 견적 데이터 저장소에 없음 |
| 예약 | 관리자 일정 기능은 있으나 고객 예약 흐름은 확인 불가 | `app/admin` |

## 전환 방해 가능 요소

- 가격 정보가 구조화되어 있지 않아 가격 비교 고객이 이탈할 수 있음
- 제작 기간과 현장 작업 시간이 서비스별로 분리되어 있지 않음
- 랜딩/SEO 페이지 수가 많아 중복 문구 리스크가 있음
- 사진을 몇 장, 어떤 각도로 보내야 하는지 모든 페이지에서 동일하게 명확하지 않을 수 있음
