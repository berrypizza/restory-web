# 리스토리 커뮤니티

고객과 기술자가 함께 쓰는 공개 게시판입니다. 로그인 화면은 기존 업무 관리용 `/admin`과 분리되어 있지만, 공유 데이터베이스의 기존 업무 권한 문제는 공개 전에 보완해야 합니다.

## 화면

- `/community`: 공개 글 목록, 4개 게시판, 제목 검색, 20개씩 페이지 이동
- `/community/login`: 카카오 로그인, 공개 닉네임 등록
- `/community/auth`: Supabase PKCE 로그인 복귀
- `/community/new`: 글 작성, JPG·PNG·WebP 사진 최대 4장
- `/community/[id]`: 본문·사진·댓글, 작성자 수정 및 삭제, 신고
- `/community/manage`: 운영자만 신고 확인·글 숨김·복구
- `/community/guide`: 공개 글·사진과 개인정보에 관한 이용 안내

게시판은 수리 질문, 작업 이야기, 기술 정보, 자유 이야기입니다. 가상 회원이나 예시 게시글을 실제 글처럼 넣지 않습니다.

## 데이터와 권한

기존 리스토리 Supabase `qbotbuipbnkpxnvhgify`에 `community_` 접두사 테이블을 추가했습니다. 업무 데이터와 일깜 프로젝트는 변경하지 않았습니다.

- `community_profiles`: 공개 닉네임. 이메일·카카오 실명은 게시판에 표시하지 않음
- `community_posts`, `community_comments`: 공개 상태만 비회원이 읽을 수 있음
- `community_moderators`: 운영자 목록. 클라이언트에서 추가·변경 불가
- `community_reports`: 작성한 신고와 운영자만 확인 가능
- `community-photos`: 비공개 Storage 버킷. 공개 게시글에 첨부된 사진만 다른 방문자가 읽을 수 있음

Supabase의 사용자 JWT와 RLS로 권한을 확인합니다. 브라우저의 역할 표시나 수정 가능한 사용자 메타데이터로 권한을 부여하지 않습니다. 일반 회원은 자신의 공개 글만 수정·삭제할 수 있고, 운영자가 숨긴 글을 스스로 복구할 수 없습니다. 운영자는 다른 사람의 본문을 바꾸지 않고 숨김 상태만 변경합니다.

글 등록은 회원별 10분에 5개, 댓글은 10분에 20개로 제한합니다. 삭제도 물리적 삭제 대신 상태 변경으로 처리하므로 반복 등록 제한을 피할 수 없습니다.

사진은 업로드 직전에 최대 긴 변 1,800px JPEG로 다시 인코딩하며 EXIF 위치정보를 제거합니다. 5분짜리 서명 URL로 표시하고 공용 이미지 최적화 캐시에 넣지 않습니다. 글을 숨기면 새 서명 URL 발급은 차단되며, 이미 발급된 URL은 남은 최대 5분 동안 유효할 수 있습니다.

## 적용 및 검증 기록 — 2026-10-27

- `supabase/migrations/20261027084513_restory_community.sql`을 실제 프로젝트에 적용했습니다.
- `scripts/test-community-rls.sql`: 13개 권한·반복 등록 검증 통과. 모든 테스트 데이터는 트랜잭션 롤백으로 제거됩니다.
- 추가 사진 권한 검사 3개 통과: 작성 전 비공개, 글 공개 후 읽기, 글 삭제 후 새 읽기 차단.
- 비회원 Data API 목록 조회 HTTP 200 확인.
- 타입 검사와 커뮤니티 코드 lint 통과. Webpack 프로덕션 빌드에서 기존 페이지를 포함한 6,846개 페이지 생성 완료.
- 로컬 프로덕션 서버의 페이지 HTTP 200 확인만으로는 화면 검증이 부족했습니다. 드라이브 루트(`R:\`) 빌드에서 CSS 연결 누락을 발견했으며, 프로젝트 하위 경로를 유지하는 개발 서버로 수정했습니다. `/repair`, `/community`의 CSS 연결과 스타일 파일 HTTP 200, 수리 페이지의 모든 로컬 스크립트 HTTP 200을 확인했습니다.
- 커뮤니티에 관한 Supabase 보안 점검의 신규 경고 없음. 기존 업무 함수·조회수 함수·비밀번호 보호 설정의 경고는 이번 범위에서 변경하지 않았습니다.

## 운영 공개 전에 남은 확인

0. **기존 업무 데이터 권한 보완이 필요합니다.** 2026-10-27 읽기 전용 메타데이터 점검에서 `jobs`, `materials`, `business_expenses` 모두 `anon`에 조회·입력·수정·삭제 권한이 있고 공개 RLS 조건도 `true`인 것을 확인했습니다. 이번 커뮤니티 migration이 만든 정책은 아닙니다. 업무 관리 화면의 직원 인증과 데이터 권한을 함께 바꾸어야 하며, 현재 업무를 중단시킬 수 있는 일괄 권한 철회는 실행하지 않았습니다. 실제 업무 데이터 내용은 이 점검에서 읽지 않았습니다.
1. 기존 카카오 로그인 공급자는 활성화되어 있습니다. Supabase Authentication URL Configuration에 `https://www.restorystudio.co.kr/community/auth`를 추가하고 실제 로그인 복귀를 검증해야 합니다. 기존 Site URL과 다른 서비스의 Redirect URL은 유지해야 합니다.
2. 운영자 계정은 대표가 지정한 기존 카카오 회원으로 확인한 뒤 `community_moderators`에 연결합니다. 현재는 자동 부여하지 않았습니다.
3. 브라우저 도구 오류로 실제 PC·모바일 화면 및 사진 첨부를 포함한 로그인 후 작성 흐름의 브라우저 검증은 아직 완료하지 못했습니다.
4. 본 사이트 공개 여부를 확인한 뒤 프로덕션에 배포합니다. 현재 브랜치의 코드 준비와 운영 사이트 배포를 구분합니다.

## Windows 로컬 검증

`npm run dev:local`로 `http://localhost:5194`를 엽니다. Windows 경로에 `!`가 있으면 실행기가 빈 드라이브 문자를 찾아 **프로젝트의 상위 폴더**를 임시 연결하고 Webpack 개발 서버를 실행합니다. 서버가 종료되면 임시 연결을 정리합니다. 원본 파일은 이동하지 않습니다.

수동 실행 예시는 `subst W: "D:\가보자!!!"` 후 `W:\restory-web`에서 실행하는 것입니다. 프로젝트 자체를 드라이브 루트에 연결하지 않습니다. Next 16.2.6의 Webpack CSS 매니페스트 키에 경로 구분자가 중복되어 HTML에서 CSS 연결이 빠질 수 있습니다.

개발 미리보기는 `RESTORY_BUILD_DIRECTORY=.next-community-local`을 사용하며, 빌드 검증에는 `.next-community-verify`를 사용할 수 있습니다. 운영 환경은 기본 `.next`를 유지합니다. 수동 검증이 끝나면 서버 종료 후 `subst W: /D`로 연결을 해제합니다.
